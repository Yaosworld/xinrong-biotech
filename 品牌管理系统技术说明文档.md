## 二、数据库设计

### 2.1 数据存储

品牌数据存储在统一的 `contents` 表中，通过 `content_type = 'brand'` 区分。

```sql
-- 品牌数据存储在 contents 表
SELECT * FROM contents WHERE content_type = 'brand';

-- 表结构
CREATE TABLE contents (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_type    TEXT NOT NULL,      -- 'brand'
  content_key     TEXT NOT NULL,      -- 品牌ID: 'B001', 'B002'
  draft_data      TEXT,               -- 草稿数据 (JSON)
  published_data  TEXT,               -- 已发布数据 (JSON)
  status          TEXT DEFAULT 'draft', -- draft/published/deleted
  version         INTEGER DEFAULT 1,  -- 版本号
  sort_order      INTEGER DEFAULT 0,  -- 排序顺序
  created_at      TEXT,
  updated_at      TEXT,
  published_at    TEXT,
  UNIQUE(content_type, content_key)
);
```

### 2.2 品牌数据模型

```typescript
interface Brand {
  id: string                // 品牌ID, e.g., "B001"
  name: string              // 品牌名称
  logo_url?: string         // Logo 图片路径
  certificate_url?: string  // 品牌授权证书图片路径
  is_own_brand?: boolean    // 是否为自主品牌
  country?: string          // 品牌国家/地区
  description?: string      // 品牌描述
  website?: string          // 官网链接
  sort_order?: number       // 排序顺序（越小越靠前）
  
  // 兼容旧字段
  brand_id?: string         // 旧ID字段
  show_name?: string        // 旧显示名称字段
  is_own?: boolean          // 旧自主品牌字段
  product_count?: number    // 关联产品数量
  website_url?: string      // 旧官网字段
}
```

## 三、后端服务

### 3.1 内容服务 (contentService)

品牌管理复用统一的内容服务，无需专门的品牌服务。

**核心方法：**

| 方法 | 说明 |
|------|------|
| `getPublishedList('brand', options)` | 获取已发布品牌列表 |
| `getAdminList('brand', options)` | 获取后台品牌列表（含草稿） |
| `saveDraft('brand', key, data)` | 保存品牌草稿 |
| `batchSaveDraft('brand', items)` | 批量保存品牌草稿 |
| `publish('brand', key, summary)` | 发布品牌 |
| `batchPublish('brand', keys, summary)` | 批量发布品牌 |
| `delete('brand', key)` | 删除品牌（软删除） |

```typescript
// 调整品牌排序（上移/下移）
function moveBrand(brandId: string, direction: 'up' | 'down') {
  const brand = brands.value.find(b => b.id === brandId)
  if (!brand) return

  // 获取同类品牌列表（自主品牌或代理品牌分开排序）
  const sameCategoryBrands = brands.value
    .filter(b => b.is_own_brand === brand.is_own_brand)
    .sort((a, b) => (a.sort_order || 999) - (b.sort_order || 999))

  const currentIndex = sameCategoryBrands.findIndex(b => b.id === brandId)
  const targetIndex = direction === 'up' ? currentIndex - 1 : currentIndex + 1
  
  if (targetIndex < 0 || targetIndex >= sameCategoryBrands.length) return

  // 交换排序值
  const targetBrand = sameCategoryBrands[targetIndex]
  const tempOrder = brand.sort_order
  brand.sort_order = targetBrand.sort_order
  targetBrand.sort_order = tempOrder
}
```

```typescript
const uploadFile = async (file: File) => {
  // 1. 验证文件类型
  const acceptTypes = props.accept.split(',').map(t => t.trim())
  if (!acceptTypes.includes(file.type)) {
    ElMessage.warning('不支持的文件类型')
    return
  }

  // 2. 验证文件大小
  if (file.size > props.maxSize * 1024 * 1024) {

  } else {

    ElMessage.error(result.error || '上传失败')
```

## 八、代码问题分析

### 8.1 数据模型问题

#### 问题1：字段命名不一致

**位置：** `src/types/models.ts`

**问题描述：**
```typescript
interface Brand {
  id: string
  brand_id?: string         // 兼容旧字段
  name: string
  show_name?: string        // 兼容旧字段
  is_own?: boolean          // 旧字段
  is_own_brand?: boolean    // 新字段
  website?: string          // 新字段
  website_url?: string      // 旧字段
}
```

**问题：** 存在多个功能相同但命名不同的字段，增加了代码复杂度。

**建议：**
- 制定数据迁移计划，统一字段命名
- 在服务端进行字段映射，前端只使用新字段名

#### 问题2：国家选项硬编码

**位置：** `BrandsList.vue`

**问题描述：**
```typescript
const countryOptions = [
  { label: '中国', value: '中国' },
  { label: '美国', value: '美国' },
  // ...
]
```

**问题：** 国家列表硬编码在组件中，不便于维护和扩展。

**建议：**
```typescript
// 方案1：提取到配置文件
// src/config/options.ts
export const COUNTRY_OPTIONS = [...]

// 方案2：从后端获取
const countryOptions = await configApi.getCountryOptions()
```

### 8.2 功能缺失问题

#### 问题3：缺少品牌详情页

### 8.3 用户体验问题

#### 问题6：Logo占位符颜色随机性

**位置：** `BrandCard.vue`

**问题描述：**
```typescript
const bgColorClass = computed(() => {
  const colors = ['bg-gradient-600', 'bg-purple-500', ...]
  const index = brandName.value.charCodeAt(0) % colors.length
  return colors[index]
})
```

**问题：** 颜色基于品牌名称首字符计算，可能导致相邻品牌颜色相同。

**建议：**
```typescript
// 使用品牌ID或更复杂的哈希算法
const index = hashCode(brand.id) % colors.length
```

#### 问题7：图片上传无压缩

**位置：** `ImageUploader.vue`, `uploadService.ts`

**问题描述：**
- 上传的图片直接保存，没有进行压缩处理
- 大图片会影响页面加载速度

**建议：**
```typescript
// 前端压缩
import imageCompression from 'browser-image-compression'
const compressedFile = await imageCompression(file, { maxSizeMB: 1 })

// 或后端压缩
import sharp from 'sharp'
const optimized = await sharp(buffer).resize(400).jpeg({ quality: 80 }).toBuffer()
```

### 8.5 安全问题

#### 问题11：SVG上传安全风险

**位置：** `uploadService.ts`

**问题描述：**
```typescript
const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'image/gif', 'image/webp', 'image/svg+xml']
```

**问题：** SVG文件可能包含恶意脚本（XSS攻击）。

**建议：**
- 移除SVG支持
- 或使用SVG清理库（如 DOMPurify）处理

#### 问题12：文件名安全处理不完善

**位置：** `uploadService.ts`

**问题描述：**
```typescript
const baseName = path.basename(originalName, ext)
  .replace(/[^a-zA-Z0-9\u4e00-\u9fa5_-]/g, '_')
  .substring(0, 50)
```

**问题：** 虽然做了基本处理，但可能存在路径遍历风险。

**建议：**
```typescript
// 更严格的文件名验证
const sanitizedName = path.basename(originalName)
  .replace(/\.\./g, '')  // 防止路径遍历
  .replace(/[^a-zA-Z0-9\u4e00-\u9fa5._-]/g, '_')
```
