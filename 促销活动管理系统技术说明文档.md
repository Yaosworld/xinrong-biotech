## 二、数据库设计

### 2.1 数据存储

促销活动数据存储在统一的 `contents` 表中，通过 `content_type = 'promotion'` 区分。

```sql
-- 促销活动数据存储在 contents 表
SELECT * FROM contents WHERE content_type = 'promotion';

-- 表结构
CREATE TABLE contents (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_type    TEXT NOT NULL,      -- 'promotion'
  content_key     TEXT NOT NULL,      -- 活动ID: 'A001', 'A002' 或数字
  draft_data      TEXT,               -- 草稿数据 (JSON)
  published_data  TEXT,               -- 已发布数据 (JSON)
  status          TEXT DEFAULT 'draft', -- draft/published/deleted
  version         INTEGER DEFAULT 1,  -- 版本号
  sort_order      INTEGER DEFAULT 0,  -- 排序顺序
  created_at      TEXT,
  updated_at      TEXT,
  published_at    TEXT,
  UNIQUE(content_type, content_key)
);

-- 版本历史表
CREATE TABLE content_versions (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_id      INTEGER NOT NULL,   -- 关联 contents.id
  version         INTEGER NOT NULL,   -- 版本号
  data            TEXT NOT NULL,      -- 版本数据快照 (JSON)
  change_summary  TEXT,               -- 变更说明
  created_at      TEXT,
  UNIQUE(content_id, version)
);
```


### 2.2 促销活动数据模型

```typescript
interface Promotion {
  id: number | string       // 活动ID, e.g., 1, 2 或 "A001"
  title: string             // 活动标题
  summary: string           // 活动摘要（简短描述）
  description?: string      // 详细描述（支持\n换行）
  cover_url?: string        // 活动封面图片路径
  poster_url?: string       // 活动海报图片路径
  icon_class?: string       // FontAwesome 图标类名
  
  // 时间信息
  publish_date?: string     // 发布日期 (YYYY-MM-DD)
  start_date?: string       // 开始日期 (YYYY-MM-DD)
  end_date?: string         // 结束日期 (YYYY-MM-DD)
  
  // 价格信息（可选）
  original_price?: number   // 原价
  current_price?: number    // 现价
  discount_badge?: string   // 折扣标签 (e.g., "8折")
  
  // 扩展信息
  tags?: string[]           // 标签数组
  applicable_products?: string  // 适用产品描述
  
  // 状态信息 (动态计算，非存储字段)
  status?: PromotionStatus  // 活动状态
  statusText?: string       // 状态文本
}

// 促销状态类型
type PromotionStatus = 'active' | 'ended' | 'coming' | 'endingSoon' | 'all'
```

### 5.2 活动状态计算逻辑

促销活动的状态是根据当前时间和活动时间范围动态计算的：

```typescript
// 状态分为四种：即将结束、正在进行、即将开始、已经结束
function calculateStatus(promotion: Promotion): { status: PromotionStatus; statusText: string } {
  // 获取北京时间（UTC+8）
  const getBeijingTime = (date?: Date): Date => {
    const d = date || new Date()
    return new Date(d.getTime() + (d.getTimezoneOffset() * 60000) + (8 * 3600000))
  }

  const now = getBeijingTime()
  const start = getBeijingTime(new Date(promotion.start_date))
  const end = getBeijingTime(new Date(promotion.end_date))
  
  // 计算距离结束的天数
  const msPerDay = 24 * 60 * 60 * 1000
  const daysUntilEnd = Math.ceil((end.getTime() - now.getTime()) / msPerDay)

  if (now < start) {
    return { status: 'coming', statusText: '即将开始' }
  } else if (now > end) {
    return { status: 'ended', statusText: '已经结束' }
  } else if (daysUntilEnd <= 5) {
    return { status: 'endingSoon', statusText: '即将结束' }  // 距离结束5天以内
  } else {
    return { status: 'active', statusText: '正在进行' }
  }
}
```

### 5.3 排序优先级

活动列表按状态优先级排序，确保用户最先看到最紧急的活动：

```typescript
// 排序优先级：即将结束(0) > 正在进行(1) > 即将开始(2) > 已结束(3)
function getStatusPriority(status: PromotionStatus): number {
  switch (status) {
    case 'endingSoon': return 0  // 即将结束 - 最高优先级
    case 'active': return 1      // 正在进行
    case 'coming': return 2      // 即将开始
    case 'ended': return 3       // 已结束 - 最低优先级
    default: return 4
  }
}

// 相同状态内部排序规则：
// - 即将结束：按结束时间升序（最快结束的在前）
// - 正在进行：按结束时间升序（最快结束的在前）
// - 即将开始：按开始时间升序（最快开始的在前）
// - 已结束：按结束时间降序（最近结束的在前）
```

### 5.5 核心方法

```typescript
// 加载促销数据（带降级机制）
async function loadPromotions() {
  if (initialized.value && promotions.value.length > 0) return

  loading.value = true
  try {
    // 优先从 API 加载
    const data = await contentApi.getAllPublished<Promotion>('promotion')
    promotions.value = data
    initialized.value = true
  } catch (e) {
    // API 失败时降级到静态 JSON
    console.warn('API 加载失败，降级到静态 JSON:', e)
    const response = await fetch('/data/promotions.json')
    if (response.ok) {
      promotions.value = await response.json()
      initialized.value = true
    }
  } finally {
    loading.value = false
  }
}

// 根据ID获取促销活动（带状态计算）
function getPromotionById(id: number): Promotion | undefined {
  const promotion = promotions.value.find(p => p.id === id)
  if (promotion) {
    const { status, statusText } = calculateStatus(promotion)
    return { ...promotion, status, statusText }
  }
  return undefined
}

// 获取封面图片路径
function getPromotionCoverPath(promotion: Promotion): string {
  return promotion.cover_url || '/images/common/placeholder.png'
}

// 获取海报图片路径
function getPromotionPosterPath(promotion: Promotion): string {
  return promotion.poster_url || '/images/common/placeholder.png'
}

// 清除缓存（发布后调用）
function clearCache() {
  promotions.value = []
  initialized.value = false
  error.value = null
}
```

```typescript
const highlightText = (text: string) => {
  if (!props.highlightKeyword || !text) return text
  
  const keywords = props.highlightKeyword
    .trim()
    .split(/\s+/)
    .filter(k => k.length > 0)
    .map(k => k.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'))
  
  if (keywords.length === 0) return text
  
  let result = text
  keywords.forEach(keyword => {
    const regex = new RegExp(`(${keyword})`, 'gi')
    result = result.replace(regex, '<mark class="search-highlight">$1</mark>')
  })
  
  return result
}
```

## 十二、代码问题分析

### 12.1 数据模型问题

#### 问题1：ID类型不一致

**问题描述：**
```typescript
interface Promotion {
  id: number | string  // 支持数字和字符串两种类型
}
```

**问题：** ID类型不统一，可能导致比较和查找时出现问题。

**建议：**
- 统一使用字符串类型 ID（如 "A001"）
- 或统一使用数字类型 ID

#### 问题2：状态字段混淆

**问题描述：**
- `status` 字段既用于数据库状态（draft/published/deleted）
- 又用于活动时间状态（active/ended/coming/endingSoon）

**建议：**
- 数据库状态使用 `contentStatus`
- 活动时间状态使用 `timeStatus` 或 `promotionStatus`


### 12.2 功能缺失问题

#### 问题3：缺少图片上传功能

**位置：** `PromotionsList.vue`

**问题描述：**
- 后台管理页面的封面和海报列配置为 `type: 'image'`
- 但没有配置 `uploadCategory`，无法直接上传图片
- 需要手动填写图片路径

**建议：**
```typescript
// 添加上传分类配置
{ 
  key: 'cover_url', 
  label: '封面', 
  type: 'image',
  uploadCategory: 'promotion-cover'  // 添加上传分类
}
```

#### 问题4：缺少活动分类功能

**问题描述：**
- 活动没有分类字段
- 无法按活动类型（如：限时促销、品牌日、新品发布等）筛选

**建议：**
- 添加 `category` 字段
- 在前台添加分类筛选功能

#### 问题5：缺少活动优先级/置顶功能

**问题描述：**
- 活动排序完全依赖状态和时间
- 无法手动调整重要活动的展示顺序

**建议：**
- 添加 `is_featured` 或 `priority` 字段
- 支持手动置顶重要活动

### 12.3 用户体验问题

#### 问题6：搜索功能单一

**位置：** `PromotionCenter.vue`

**问题描述：**
- 只支持关键词搜索
- 缺少按状态、日期范围、标签筛选

**建议：**
```typescript
// 扩展筛选条件
interface PromotionFilters {
  search: string
  status?: PromotionStatus  // 按状态筛选
  dateRange?: [string, string]  // 按日期范围筛选
  tags?: string[]  // 按标签筛选
}
```

#### 问题7：详情页缺少相关活动推荐

**位置：** `PromotionDetail.vue`

**问题描述：**
- 详情页只展示当前活动
- 没有推荐相关或热门活动

**建议：**
- 添加"相关活动"或"热门活动"区块
- 基于标签或时间推荐

### 12.4 性能问题

#### 问题8：活动列表无懒加载

**位置：** `PromotionCenter.vue`

**问题描述：**
- 活动封面图片没有使用懒加载
- 页面初始加载时会请求所有可见图片

**建议：**
```vue
<img v-lazy="promotionCoverPath" />
<!-- 或使用 Intersection Observer -->
```

#### 问题9：状态计算重复执行

**位置：** `promotionStore.ts`

**问题描述：**
- `processedPromotions` 每次访问都会重新计算所有活动的状态
- 状态计算涉及日期操作，有一定开销

**建议：**
- 使用缓存机制
- 或在数据加载时一次性计算状态


### 12.5 代码质量问题

#### 问题10：时区处理复杂

**位置：** `promotionStore.ts`

**问题描述：**
```typescript
const getBeijingTime = (date?: Date): Date => {
  const d = date || new Date()
  return new Date(d.getTime() + (d.getTimezoneOffset() * 60000) + (8 * 3600000))
}
```

**问题：** 手动计算时区偏移容易出错，且不考虑夏令时。

**建议：**
- 使用 `dayjs` 或 `date-fns` 等日期库处理时区
- 或在服务端统一处理时区

#### 问题11：硬编码的配置值

**位置：** 多处

**问题描述：**
```typescript
// 硬编码的"即将结束"天数阈值
if (daysUntilEnd <= 5) {
  return { status: 'endingSoon', statusText: '即将结束' }
}

// 硬编码的分页大小
{ initialPageSize: 8, scrollTarget: '.promotion-section' }
```

**建议：**
- 提取到配置文件
- 或作为组件 props 传入

```
GET  /api/content/promotion/published       获取已发布活动列表
GET  /api/content/promotion/:key/published  获取单条已发布活动
GET  /api/content/promotion/filter-options  获取筛选选项

后台API:
GET  /api/admin/content/promotion           获取后台活动列表
GET  /api/admin/content/promotion/:key      获取单条活动详情
GET  /api/admin/content/promotion/:key/versions 获取版本历史
PUT  /api/admin/content/promotion/:key/draft 保存草稿
PUT  /api/admin/content/promotion/batch-draft 批量保存草稿
POST /api/admin/content/promotion/:key/publish 发布
POST /api/admin/content/promotion/batch-publish 批量发布
POST /api/admin/content/promotion/:key/rollback 回滚
DELETE /api/admin/content/promotion/:key    删除
POST /api/admin/content/promotion/batch-delete 批量删除
```

### 14.3 数据字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | number/string | 是 | 活动ID |
| title | string | 是 | 活动标题 |
| summary | string | 是 | 活动摘要 |
| description | string | 否 | 详细描述（支持换行） |
| cover_url | string | 否 | 封面图片路径 |
| poster_url | string | 否 | 海报图片路径 |
| icon_class | string | 否 | FontAwesome图标类名 |
| publish_date | string | 否 | 发布日期 (YYYY-MM-DD) |
| start_date | string | 是 | 开始日期 (YYYY-MM-DD) |
| end_date | string | 是 | 结束日期 (YYYY-MM-DD) |
| tags | string[] | 否 | 标签数组 |

### 14.4 状态说明

**数据库状态 (contents.status)：**
| 状态 | 说明 |
|------|------|
| draft | 草稿（未发布） |
| published | 已发布 |
| deleted | 已删除（软删除） |

**活动时间状态 (动态计算)：**
| 状态 | 说明 | 判断条件 |
|------|------|----------|
| coming | 即将开始 | 当前时间 < 开始时间 |
| active | 正在进行 | 开始时间 ≤ 当前时间 ≤ 结束时间，且距结束 > 5天 |
| endingSoon | 即将结束 | 开始时间 ≤ 当前时间 ≤ 结束时间，且距结束 ≤ 5天 |
| ended | 已结束 | 当前时间 > 结束时间 |
