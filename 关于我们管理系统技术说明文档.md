### 1.2 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | Vue 3 + TypeScript | Composition API |
| 状态管理 | Pinia | 响应式状态管理 |
| UI组件库 | Element Plus | 后台管理UI |
| 样式 | Tailwind CSS | 原子化CSS |
| 后端框架 | Express | Node.js Web框架 |
| 数据库 | SQLite (sql.js) | 轻量级嵌入式数据库 |

### 1.3 页面特点

"关于我们"是一个**单页面内容管理**模块，与产品、品牌等列表型数据不同：
- 只有一条数据记录（content_key = 'main'）
- 包含多个内容区块（公司介绍、核心优势、联系方式）
- 支持可视化编辑和实时预览
- 联系方式数据来自网站配置（siteStore）

## 二、数据库设计

### 2.1 数据存储

关于我们数据存储在统一的 `contents` 表中，通过 `content_type = 'about'` 和 `content_key = 'main'` 标识。

```sql
-- 关于我们数据存储
SELECT * FROM contents WHERE content_type = 'about' AND content_key = 'main';

-- 表结构
CREATE TABLE contents (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_type    TEXT NOT NULL,      -- 'about'
  content_key     TEXT NOT NULL,      -- 'main'（固定值）
  draft_data      TEXT,               -- 草稿数据 (JSON)
  published_data  TEXT,               -- 已发布数据 (JSON)
  status          TEXT DEFAULT 'draft', -- draft/published/deleted
  version         INTEGER DEFAULT 1,  -- 版本号
  sort_order      INTEGER DEFAULT 0,  -- 排序顺序
  created_at      TEXT,
  updated_at      TEXT,
  published_at    TEXT,
  UNIQUE(content_type, content_key)
);

-- 版本历史表
CREATE TABLE content_versions (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_id      INTEGER NOT NULL,
  version         INTEGER NOT NULL,
  data            TEXT NOT NULL,      -- 版本数据快照 (JSON)
  change_summary  TEXT,               -- 变更说明
  created_at      TEXT,
  UNIQUE(content_id, version)
);
```

## 三、后端服务

### 3.1 内容服务 (contentService)

关于我们管理复用统一的内容服务，使用固定的 `content_key = 'main'`。

**核心方法：**

| 方法 | 说明 |
|------|------|
| `getPublishedOne('about', 'main')` | 获取已发布的关于我们数据 |
| `getOne('about', 'main')` | 获取关于我们详情（含草稿） |
| `saveDraft('about', 'main', data)` | 保存关于我们草稿 |
| `publish('about', 'main', summary)` | 发布关于我们页面 |
| `getVersions('about', 'main')` | 获取版本历史 |
| `rollback('about', 'main', version)` | 回滚到指定版本 |

**与列表型数据的区别：**
- 不需要批量操作（batchSaveDraft、batchPublish）
- 不需要删除操作（页面始终存在）
- 只有一条记录，无需分页

### 5.3 核心方法

```typescript
// 加载关于我们页面数据（带降级机制）
async function loadAboutData() {
  // 如果已经加载过，直接返回
  if (loaded.value) {
    return pageData.value
  }

  loading.value = true
  error.value = null

  try {
    // 优先从 API 加载
    const data = await contentApi.getPublishedOne<AboutPageData>('about', 'main')
    pageData.value = data
    loaded.value = true
    return pageData.value
  } catch (e) {
    // API 失败时降级到静态 JSON
    console.warn('API 加载失败，降级到静态 JSON:', e)
    try {
      const response = await fetch('/data/about.json')
      if (response.ok) {
        pageData.value = await response.json()
        loaded.value = true
        return pageData.value
      }
    } catch {
      error.value = '加载关于我们数据失败'
    }
    return null
  } finally {
    loading.value = false
  }
}

// 重新加载数据
function reload() {
  loaded.value = false
  return loadAboutData()
}

// 清除缓存（发布后调用）
function clearCache() {
  pageData.value = null
  loaded.value = false
  error.value = null
}
```

```typescript
  formData.value.advantages.splice(index, 1)
```

### 9.5 离开页面保护

```typescript
// 浏览器关闭/刷新保护
const handleBeforeUnload = (e: BeforeUnloadEvent) => {
  if (hasUnsavedChanges.value) {
    e.preventDefault()
    e.returnValue = ''
  }
}

// Vue Router 路由离开保护
onBeforeRouteLeave(async (_to, _from, next) => {
  if (hasUnsavedChanges.value) {
    try {
      await ElMessageBox.confirm('您有未保存的更改，确定要离开吗？', '提示',
        { confirmButtonText: '离开', cancelButtonText: '留下', type: 'warning' })
      next()
    } catch { next(false) }
  } else { next() }
})

// 生命周期管理
onMounted(() => {
  loadData()
  window.addEventListener('beforeunload', handleBeforeUnload)
})

onBeforeUnmount(() => {
  window.removeEventListener('beforeunload', handleBeforeUnload)
})
```

## 十、降级机制

### 10.1 前台数据降级

当 API 不可用时，前台自动降级到静态 JSON 文件：

```typescript
// aboutStore.ts
async function loadAboutData() {
  try {
    // 优先从 API 加载
    const data = await contentApi.getPublishedOne<AboutPageData>('about', 'main')
    pageData.value = data
    loaded.value = true
    return pageData.value
  } catch (e) {
    // API 失败时降级到静态 JSON
    console.warn('API 加载失败，降级到静态 JSON:', e)
    try {
      const response = await fetch('/data/about.json')
      if (response.ok) {
        pageData.value = await response.json()
        loaded.value = true
        return pageData.value
      }
    } catch {
      error.value = '加载关于我们数据失败'
    }
    return null
  } finally {
    loading.value = false
  }
}
```

## 十一、代码问题分析

### 11.1 现有问题

| 问题 | 描述 | 影响 | 建议 |
|------|------|------|------|
| 联系方式分离 | 联系方式存储在 siteStore，与关于我们页面分离 | 编辑时需要跳转到网站配置 | 可在关于我们编辑页面添加联系方式快捷入口 |
| 图标选择有限 | 只提供16个常用图标 | 用户选择受限 | 可扩展图标库或支持自定义图标 |
| 无图片上传 | 介绍卡片和优势项只支持图标 | 无法展示图片内容 | 可添加图片上传功能 |
| 预览与实际有差异 | 后台预览样式与前台略有不同 | 可能造成预期偏差 | 统一预览样式或提供"查看前台"按钮 |

### 11.2 潜在风险

1. **数据一致性**
   - 联系方式来自 siteStore，关于我们内容来自 aboutStore
   - 两者发布时机可能不同步
   - 建议：添加关联发布提醒

2. **版本管理**
   - 版本历史只记录关于我们内容
   - 不包含联系方式的变更历史
   - 建议：在版本快照中记录关联数据引用

3. **缓存同步**
   - 发布后调用 `aboutStore.clearCache()` 清除缓存
   - 但前台可能仍有浏览器缓存
   - 建议：添加版本号或时间戳参数

### 11.3 代码质量

**优点：**
- 组件结构清晰，职责分明
- 状态管理规范，使用 Pinia
- 支持实时预览，用户体验好
- 有完善的离开保护机制

**待改进：**
- 部分样式可抽取为公共组件
- 图标选择器可封装为独立组件
- 表单验证可更完善（如必填项检查）
