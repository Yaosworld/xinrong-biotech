## 二、数据库设计

### 2.1 核心表结构

#### contents 表（统一内容表）

```sql
CREATE TABLE contents (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_type    TEXT NOT NULL,      -- 内容类型: 'product', 'category', 'brand'
  content_key     TEXT NOT NULL,      -- 内容唯一标识: 'P1001', 'C01'
  draft_data      TEXT,               -- 草稿数据 (JSON)
  published_data  TEXT,               -- 已发布数据 (JSON)
  status          TEXT DEFAULT 'draft', -- 状态: draft/published/deleted
  version         INTEGER DEFAULT 1,  -- 版本号
  sort_order      INTEGER DEFAULT 0,  -- 排序顺序
  created_at      TEXT,
  updated_at      TEXT,
  published_at    TEXT,
  UNIQUE(content_type, content_key)
);
```

#### content_versions 表（版本历史）

```sql
CREATE TABLE content_versions (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  content_id      INTEGER NOT NULL,   -- 关联 contents.id
  version         INTEGER NOT NULL,   -- 版本号
  data            TEXT NOT NULL,      -- 版本数据快照 (JSON)
  change_summary  TEXT,               -- 变更说明
  created_at      TEXT,
  UNIQUE(content_id, version)
);
```

#### category_images 表（分类图片）

```sql
CREATE TABLE category_images (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  filename        TEXT NOT NULL UNIQUE, -- 文件名（唯一）
  original_name   TEXT NOT NULL,        -- 原始文件名
  path            TEXT NOT NULL,        -- 相对路径
  created_at      TEXT
);
```


### 2.2 数据模型

#### 产品数据 (Product)

```typescript
interface Product {
  id: string            // 产品ID, e.g., "P1001"
  name: string          // 产品名称
  categoryId: string    // 分类ID (外键)
  brand?: string        // 品牌名称
  sku?: string          // 产品SKU编码
  specs: string         // 规格参数
  unit?: string         // 销售单位
  desc: string          // 产品详细描述
}
```

#### 分类数据 (Category)

```typescript
interface Category {
  id: string            // 分类ID, e.g., "C01"
  name: string          // 分类名称
  imageId?: number      // 关联的图片ID（新架构）
  imageName?: string    // 图片文件名（旧架构兼容）
  imageUrl?: string     // 图片完整URL（服务端计算）
  description?: string  // 分类描述
}
```

### 2.3 数据关系

```
┌─────────────┐     1:N      ┌─────────────┐
│  Category   │◄─────────────│   Product   │
│  (分类)     │  categoryId  │   (产品)    │
└─────────────┘              └─────────────┘
       │
       │ 1:1 (imageId)
       ▼
┌─────────────────┐
│ CategoryImage   │
│ (分类图片)      │
└─────────────────┘
```

**关键设计点：**
- 产品通过 `categoryId` 关联分类（多对一）
- 分类通过 `imageId` 关联图片（一对一）
- 产品图片复用分类封面图（核心业务逻辑）

### 8.1 ExcelProcessor（Excel处理器）

**功能：**
- 解析Excel文件
- 验证数据格式

- 格式化产品数据

**核心方法：**

```typescript
// 1. 处理产品数据
static async processProducts(file, existingIds, options) {
  const XLSX = await import('xlsx')
  const workbook = XLSX.read(await file.arrayBuffer())
  const data = XLSX.utils.sheet_to_json(workbook.Sheets[workbook.SheetNames[0]])
  
  const validation = this.validateProductData(data, options?.skipCategoryValidation)
  const formattedData = this.formatProductsData(data, existingIds, options?.newCategoryMap)
  
  return { success: validation.isValid, data: formattedData, validation }
}

// 2. 验证产品数据
static validateProductData(data, skipCategoryValidation = false) {
  const requiredFields = ['name', 'categoryId', 'specs', 'desc']
  const errors: string[] = []
  const undefinedCategories: string[] = []
  
  data.forEach((row, index) => {
    // 检查必填字段
    requiredFields.forEach(field => {
      if (!row[field]) errors.push(`第${index + 2}行: 缺少必填字段 "${field}"`)
    })
    // 检查分类有效性
    if (row.categoryId && !skipCategoryValidation) {
      const normalizedId = this.normalizeCategoryId(row.categoryId)
      if (!normalizedId) undefinedCategories.push(row.categoryId)
    }
  })
  
  return { isValid: errors.length === 0, errors, undefinedCategories }
}

// 3. 格式化产品数据（自动生成ID，处理分类映射）
static formatProductsData(data, existingIds, newCategoryMap) {
  const usedIds = new Set(existingIds || [])
  let maxIdNum = Math.max(...[...usedIds].map(id => parseInt(id?.replace(/^P/, '') || '0')))
  
  return data.map(row => {
    // 生成ID
    let id = row.id
    if (!id || usedIds.has(id)) {
      maxIdNum++
      id = `P${maxIdNum}`
    }
    usedIds.add(id)
    
    // 处理分类ID
    let categoryId = null
    if (newCategoryMap?.has(row.categoryId)) {
      categoryId = newCategoryMap.get(row.categoryId)
    } else {
      categoryId = this.normalizeCategoryId(row.categoryId)
    }
    if (!categoryId) categoryId = 'C00' // 未分类
    
    return { id, name: row.name, categoryId, ... }
  })
}
```

### 8.2 useCategoryImage（分类图片Hook）

**功能：**

```typescript
export function getCategoryImagePath(id: string): string {
  const category = getCategoryById(id)
  // 优先使用 imageUrl（新架构）
  if (category?.imageUrl) return category.imageUrl
  // 降级到 imageName（旧架构）

  return '/images/common/placeholder.png'
}

// Composable Hook
export function useCategoryImage(categoryId: Ref<string> | string): ComputedRef<string> {
  return computed(() => {
    const id = typeof categoryId === 'string' ? categoryId : categoryId.value
    return getCategoryImagePath(id)
  })
}

// 带错误处理的版本
export function useCategoryImageWithFallback(categoryId, fallback) {
  const imagePath = computed(() => getCategoryImagePath(id) || fallback)
  const handleError = (event: Event) => {
    const img = event.target as HTMLImageElement
    if (img.src !== fallback) img.src = fallback
  }
  return { imagePath, handleError }
}
```

## 十、代码问题分析

### 10.1 架构层面问题

#### 问题1：分类服务存在两个版本
**位置：** `categoryService.ts` 和 `categoryServiceV2.ts`

**问题描述：**
- 存在两个分类服务文件，功能重叠
- 可能导致维护混乱，不清楚应该使用哪个

**建议：**
- 统一为一个服务文件
- 如果V2是重构版本，应完成迁移后删除旧版本

#### 问题2：图片关联存在新旧两种方式
**位置：** `categoryService.ts`, `categoryImageService.ts`

**问题描述：**
```typescript
// 新方式：通过 imageId 关联
if (cat.imageId) { ... }
// 旧方式：通过 imageName 关联
else if (cat.imageName) { ... }
```

**建议：**
- 制定数据迁移计划，将旧数据迁移到新架构
- 设置过渡期后移除旧方式支持

### 10.2 数据一致性问题

#### 问题3：产品数量统计可能不准确
**位置：** `categoryService.ts` - `getCategoriesWithCount()`

**问题描述：**
- 统计逻辑需要遍历所有产品并解析JSON
- 大数据量时性能较差
- 每次请求都重新计算，无缓存

**建议：**
```typescript
// 方案1：添加缓存
const countCache = new Map<string, number>()
const cacheExpiry = 60000 // 1分钟

// 方案2：使用数据库触发器或定时任务更新计数
// 在 contents 表添加 category_product_count 字段
```

#### 问题4：草稿和发布数据的优先级处理
**位置：** 多处

**问题描述：**
```typescript
// 有时优先草稿
const data = row.draft_data || row.published_data
// 有时只看发布
WHERE status = 'published' AND published_data IS NOT NULL
```

**建议：**
- 明确定义不同场景的数据优先级规则
- 后台管理：优先草稿
- 前台展示：只看发布
- 统计计数：根据业务需求决定

### 10.3 前端问题

#### 问题5：categoryOptions 响应性问题
**位置：** `ProductsList.vue`

**问题描述：**
```typescript
const columns = computed(() => [
  { 
    key: 'categoryId', 
    options: categoryOptions.value  // 这里取的是 .value
  }
])
```

**问题：** `categoryOptions.value` 在 computed 内部取值，当 categoryStore 更新时，columns 会重新计算，但 options 可能不会正确更新。

**建议：**
```typescript
// 方案1：直接传递 computed
options: categoryOptions  // 不加 .value

// 方案2：在 UnifiedTableEditor 中处理
// 检测 options 是否是 Ref，如果是则自动解包
```

#### 问题6：Excel导入错误处理不完善
**位置：** `ProductsList.vue` - `handleExcelImport()`

**问题描述：**
```typescript
throw new Error('__PENDING_CATEGORY_DEFINITION__')
```

**问题：** 使用特殊错误字符串来控制流程，不够优雅

**建议：**
```typescript
// 方案1：使用自定义错误类
class PendingCategoryError extends Error {

  }
```

#### 问题7：usedImagesMap 类型不一致
**位置：** `CategoryImagePicker.vue`

**问题描述：**
```typescript
props: {
  usedImagesMap?: Map<number, string> | Record<string, string>

```

**问题：** 支持两种类型增加了处理复杂度

**建议：**
- 统一使用 `Map<number, string>` 类型
- 在调用方进行类型转换


### 10.4 性能问题

#### 问题8：大数据量导入性能
**位置：** `contentService.ts` - `batchSaveDraft()`

**问题描述：**
- 虽然使用了 `batchOperation` 减少磁盘写入
- 但仍然是逐条 INSERT/UPDATE，大数据量时较慢

**建议：**
```typescript
// 使用批量 INSERT 语法
const values = items.map(i => `(?, ?, ?, ?, ?, ?)`).join(',')

```

#### 问题9：分类图片列表无分页
**位置：** `CategoryImageList.vue`, `categoryImageService.ts`

**问题描述：**
- `getAll()` 返回所有图片，无分页

- 或使用虚拟滚动
